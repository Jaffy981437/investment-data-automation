# 庫存與成本自動化 — 規劃

> 建立日期:2026-08-06
> 前提:5 家券商 —— 永豐、新光、富邦、土銀、Firstrade;目前全部只用手機操作,電腦端空白。
> 相關文件:[方舟運算_操作流程.md](方舟運算_操作流程.md)

---

## 一、先講結論

原本的想法是「5 家券商全部走社群那條 GUI 自動化路線」。查證後結論是:

**不該全部走 GUI。5 家裡有 2 家有官方免費 Python API,可以直接查庫存與成本。**

GUI 自動化應該只用在**真正沒有替代方案**的地方,也就是:土銀、Firstrade,以及寫回方舟 APP。

理由很現實:GUI 腳本是按畫面位置點擊,券商一改版就失效。5 家全走 GUI = 5 套腳本要維護,這個專案會被維護成本壓垮。

## 二、5 家券商現況盤點

| 券商 | 電腦端 | 官方 API | 建議路線 | 納入自動化 |
|---|---|---|---|---|
| **永豐** | eLeader / 網頁 | ✅ **Shioaji**(Python,免費) | **API** | ✅ 試點 |
| **Firstrade** | 純網頁 | ❌ 無公開 API | 網頁 DOM | ✅ |
| **土銀** | APGO 下單軟體 + 網頁 | ❌ 查無 | 網頁 DOM | ✅ |
| **新光證券** | 網頁 / 下單軟體 | ❌ 查無公開資料 | 網頁 DOM | ✅ |
| **富邦** | 新一代 / 網頁 | ✅ Fubon Neo(Python,免費) | API | ⬜ 本人決定暫不納入 |

### 兩個 API 的關鍵能力

- **永豐 Shioaji**:`list_positions()` 直接回傳持股代碼、數量、平均成本、現價、損益。
- **富邦 Neo**:`sdk.accounting.inventories()` 查庫存。支援 Python / C# / Node.js。

兩家都是**客戶免費申請**,不需額外付費。

### 新光證券(已確認)

本人確認是**新光證券**(skis.com.tw,獨立券商),不是新光金旗下的元富證券。

搜尋「新光證券 API」的結果全部指向元富的數位 API 專區,**新光證券本身查不到公開的程式交易 API**。
結論:與土銀同一層,走網頁 DOM。若你之後問營業員得知有 API,再拉回 API 路線。

> 順帶一提:元富證券(新光金旗下)確實有支援 Python 的 API 專區。若你名下剛好也有元富帳戶,那家可以走 API。

### Firstrade 的限制(你選的試點)

官方說明頁明確寫著:**當前持倉與成本無法匯出 CSV**。可匯出的只有:

- 近三年交易紀錄(Tax Center → Download Account Information)
- 前一稅務年度的損益(Gain/Loss → Download CSV)

原文:「Current-year realized/unrealized data ... cannot be downloaded in CSV format at this time.」

所以 Firstrade 拿當前庫存只有兩條路:

1. **讀 Positions 頁面的 DOM**(建議)—— 你登入後,我讀網頁表格文字
2. 下載交易紀錄 CSV,自己重算持倉與成本 —— 要處理拆股、股息再投資、配股,複雜且容易錯

## 三、架構:兩段分開處理

```
[A 段] 券商 → 統一庫存 csv
   ├─ 永豐    → Shioaji API          (全自動,你只需開通一次)
   ├─ 富邦    → Fubon Neo API        (全自動,你只需開通一次)
   ├─ 新光    → 待確認
   ├─ 土銀    → 你登入後,讀網頁 DOM
   └─ Firstrade → 你登入後,讀網頁 DOM
                    ↓
        data/holdings/holdings_latest.csv   ← 統一格式,已定義
                    ↓
   ├─ reports/ 持股摘要(已完成)
   └─ Google Drive 保留歷史快照(你要的「雲端留一份」)
                    ↓
[B 段] 統一庫存 csv → 方舟運算 APP
   └─ MuMuPlayer 模擬器 + Computer Use 點畫面   ← 唯一沒有替代方案的一段
```

**A 段與 B 段可以完全獨立開發。**A 段做完就已經有庫存紀錄與報表,B 段做不做都不影響。

## 四、能力邊界 — 我能做什麼、不能做什麼

這決定了自動化的天花板,先講清楚免得規劃到一半才發現卡住。

### 我不能做(硬性限制,不會因為授權而改變)

- **輸入帳號、密碼、憑證密碼** —— 任何券商、任何情境都不行
- **執行下單、買賣、資金移轉**
- **提供個人化投資建議**

### 我能做

- 你**登入完成後**,操作已登入的視窗:點選單、切頁籤、按匯出、讀畫面表格
- 讀取你放在 `.env` 的設定(你自己填,我不會把內容印出來或寫進版控)
- 寫程式呼叫 API、處理 csv、產報表
- 控制模擬器操作方舟運算 APP

### 直接後果:全自動無人值守排程在你這走不通

登入這一步永遠需要你。所以現實的目標是:

> **你登入 → 喊一聲 → 剩下全部自動跑完**

社群裡有人回報「排程有跑但券商沒自動登入」,撞的就是這堵牆。API 路線是唯一例外 —— 開通後憑證存在本機,程式可自行登入,那才是真正的全自動。

**這是 API 路線比 GUI 路線強的第二個理由。**

## 五、統一庫存格式(已定義並可用)

`data/holdings/holdings.example.csv`:

```csv
date,code,name,market,shares,avg_cost,currency,broker,note
```

- `shares` 保留完整小數位(美股常有碎股;方舟輸入也要求完整精度)
- `avg_cost` 原始精度存檔,要寫回方舟時才四捨五入到小數點後 2 位
- `broker` 區分 5 家券商,合併後仍看得出來源
- 檔案不進 git,但留在 Google Drive = 你要的雲端備份

## 七、風險與原則

1. **不做無人值守的自動寫入。** 方舟的更新流程包含「清空布局自選」這種刪除動作。社群自己發生過「更新到另一個帳號的庫存」。先產差異報告、人工確認、再寫入。
2. **GUI 腳本會因改版失效。** 這是宿命,不是寫得好就能避免。所以能用 API 的絕不用 GUI。
3. **API 憑證是高價值資產。** 一律放 `.env`,不進版控、不上傳、不貼進對話。
4. **程式只負責取得與呈現資料。** 買賣決策與下單由本人執行;方舟產出的是建議,不是指令。
